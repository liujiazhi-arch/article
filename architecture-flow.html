2. 三条最常用流程

命令行审查/修复

  • 1用户执行 thesis-workbench audit/apply
  • 2thesis_workbench.py 解析参数和 profile
  • 3workflow.py 按 scope 编排
  • 4audit_thesis.py 检查，fix_thesis.py 修复
  • 5输出报告或新的 DOCX

本地 API 处理单篇论文

  • 1用户执行 article-api 或 article-local serve
  • 2app.py 暴露 /audit、/apply、/jobs
  • 3同步请求直接进入 article_engine.service
  • 4异步请求进入 jobs.py 和 job_runner.py
  • 5状态写入 storage.py，文件由 uploads.py 管理

本地运维

  • 1article-local init 初始化 state/runtime
  • 2doctor 检查 SQLite、runtime、任务恢复状态
  • 3maintain 做状态库维护
  • 4backup/restore 分层打包状态和运行产物
  • 5这些职责已经从 local_app.py 拆到独立模块

3. 文件职责地图

scripts/thesis_workbench.py
面向命令行用户的主入口，负责把 audit/plan/apply/verify 命令转给 workflow。
scripts/article_api/local_app.py
本地壳入口，现在只做 CLI 参数、命令分发和 console script alias。
scripts/article_api/app.py
FastAPI 路由层，暴露同步处理、上传、异步任务、运维状态接口。
scripts/article_api/jobs.py
异步 job 生命周期：queued/running/succeeded/failed、retry、cleanup、artifact。
scripts/article_api/storage.py
SQLite 状态层，保存 job、upload、cleanup、retention 等状态。
scripts/article_engine/service.py
统一服务层，把 CLI/API 请求包装成稳定 payload，再调用核心工具。
scripts/thesis_tool/workflow.py
论文处理编排层，负责 scope 计划、修复、复查的组合逻辑。
scripts/audit_thesis.py
规则检查 runtime，读取 profile，扫描 DOCX 并生成问题结果。
scripts/fix_thesis.py
自动修复核心，按 scope 写出新 DOCX，并保护结构稳定性。
scripts/_thesis_utils.py
DOCX 结构底座，包含 DocumentModel、ParagraphNode、章节/模块分类。
config/
profile、能力矩阵、模板注入材料，是规则行为的配置来源。
references/lnu/
保留辽大官方 PDF/DOC 参考文件，不再存旧聊天记忆和历史 handoff。

4. 已删除/下线的内容

批量处理 article-local batch、/batch、/jobs/batch 已下线。
历史脚本 scripts/legacy/ 已删除，不再保留旧实验脚本。
npm 包装 package.json 已删除，统一走 Python 和 console scripts。
旧记忆文档 旧交接、日志、memory、handoff 文档已清理，避免维护噪音。
