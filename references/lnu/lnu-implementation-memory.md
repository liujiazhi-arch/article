# 辽大专项能力与经验记忆清单

日期：2026-04-08

用途：作为后续处理辽宁大学本科毕业论文时的执行记忆、能力清单与迭代记录。

## 1. 当前已经稳定具备的能力

### 1.1 辽大序言编号规则

- 已支持 `序言 -> 序  言` 规范化。
- 已支持序言子级按 `0.1`、`0.1.1`、`0.1.1.1` 递进。
- 已支持后续正文章节从 `1` 开始顺延。
- 已支持对修前状态做诊断：
  - `zero_based_mismatch`
  - `zero_based_ok`

### 1.2 目录链路

- 已支持识别手工目录、自动目录域、重复目录。
- 已支持清理旧目录后重建 TOC 域。
- 已支持诊断目录状态：
  - `no_toc`
  - `manual_toc`
  - `field_only`
  - `generated_toc`
  - `duplicate_toc`
- 已明确区分：
  - 工具负责目录结构正确
  - Word/WPS 负责目录页码刷新显示

### 1.3 标题结构识别

- 已支持对错样式标题做纠偏，例如：
  - 文本是 `3.6 分子对接验证结果`
  - 样式却是 `Heading 1`
  - 仍能识别为二级标题风险
- 已支持跳过表格内容对标题重编号的污染。
- 已支持识别并报告样式/文本层级冲突。

### 1.4 正文误挂标题样式降级

- 已支持将“误套 Heading 样式的正文句子”在正文修复时降回普通正文样式。
- 目的不是只让分类结果变对，而是避免 Word 导航、目录、页内结构继续被错误样式污染。

### 1.5 辽大专项诊断能力

已支持 `thesis_workbench.py diagnose`。

当前可输出：

- 目录状态
- 辽大序言编号状态
- 正文标题链
- 表格伪标题风险
- 样式/文本层级冲突
- 建议动作

已支持紧凑摘要：

```bash
python3 scripts/thesis_workbench.py diagnose <docx> --profile lnu --compact
```

适合批量筛查的稳定字段包括：

- `toc_status`
- `preface_status`
- `heading_count`
- `table_heading_risk_count`
- `table_heading_risk_summary`
- `style_conflict_count`
- `recommended_action_count`

## 2. 今晚处理过程中确认过的关键经验

### 2.1 先修结构识别，再修格式结果

如果结构识别错了，后面的排版修复越多，可能错得越远。

典型表现：

- 表格内容被算入标题链
- 错样式标题被当成一级标题
- 目录残留和新目录叠加

结论：

- 遇到标题编号错乱时，先查“哪些段落被认成了标题”
- 不要先直接改章节数字

### 2.2 辽大规则必须工具内化，不能靠人提醒

今晚最典型的就是 `序言 0.1` 规则。

结论：

- 只要是辽大专项规则，就要沉入工具和回归测试
- 不要依赖“下次记得提醒”

### 2.3 目录问题必须拆成两层

目录问题分为两类：

- 结构问题：旧目录没清掉、目录重复、没有 TOC 域
- 渲染问题：Word/WPS 还没刷新页码显示

结论：

- 以后不能把这两件事混成一个状态
- 修复完成后应明确告诉用户是否还需 `Ctrl+A` + `F9`

### 2.4 不要为了诊断更好看去污染主链

今晚批判型 Agent 提醒得最有价值的一点：

- 诊断层可以增强
- 共享分类函数和主修复链必须谨慎

结论：

- 优先在 `workflow.py diagnose` 层做观测增强
- 只有在回归足够充分时，才把规则下沉进 `fix_thesis`

### 2.5 测试必须围绕事故写

最有价值的测试不是抽象覆盖率，而是事故回归：

- `1 序言` 必须识别为 `zero_based_mismatch`
- 修后必须变成 `zero_based_ok`
- `3.6 分子对接验证结果` 的样式冲突必须能抓到
- 表格中的化合物名和科学计数法不能污染重编号链
- 正文误挂 `Heading 1` 样式必须能降回正文

## 3. 后续处理辽大论文时的推荐执行顺序

### 3.1 标准流程

1. 先跑 `diagnose --profile lnu`
2. 看 `toc_status`
3. 看 `preface_status`
4. 看正文标题链是否连续
5. 看 `style_text_conflicts`
6. 看 `table_heading_risk_summary`
7. 再决定是否执行：
   - `headings`
   - `toc`
   - `body_paragraphs`
   - `--renumber-headings`

### 3.2 推荐判断准则

- 若 `preface_status=zero_based_mismatch`
  - 优先处理 `headings`
  - 通常要带 `--renumber-headings`

- 若 `toc_status=manual_toc` 或 `duplicate_toc`
  - 优先处理 `toc`
  - 通常要带 `--toc`

- 若 `style_conflict_count>0`
  - 先核标题层级
  - 再决定是否做标题修复

- 若 `table_heading_risk_count>0`
  - 先看表格风险摘要
  - 不要直接信任重编号结果

## 7. 追加记忆：本轮守卫与伪标题统一的经验

### 7.1 apply 守卫必须服务主链，而不是反过来卡主链

本轮确认了一条很重要的边界：

- `table_heading_risk_count` 适合作为告警信号
- 不适合作为 `headings + --renumber-headings` 的硬阻断条件

原因：

- 辽大主修复链本身已经跳过表格段落，不会把表格内容直接重编号进正文标题链
- 如果把“表格风险多”直接当成阻断条件，会误拦可以安全完成的论文

## 8. 追加记忆：表块要按对象块处理，不能只修表名

### 8.1 新确认规则

- 辽大表块的正确处理链应是：
  - 上文
  - 表名
  - 表格本体
  - 表注（若有）
  - 下文
- 表名与上文之间要有可见间隔。
- 表名段后必须为 `0`，确保贴表。
- 表块结束后必须与下文或后续图块留出可见间隔。

### 8.2 工程结论

- 仅修表名字体、字号和居中，不足以解决真实论文中的表格排版问题。
- 表格相关规则也必须像图块一样，按“对象块”整体结算，而不是只盯住一个段落。
- 2026-04-14 已新增 `LNU_TB04`，后续遇到同类问题优先按工具回归处理。

## 9. 追加记忆：WPS 视角下的图表留白与公式横线事故

日期：2026-04-15

### 9.1 这次问题是怎么发生的

本轮不是单一问题，而是三类问题叠加：

- 公式下方出现粗横线
  - 根因不是公式对象本身，而是“公式布局表”被当成普通表格执行了三线表修复。
  - Word/WPS 中这类公式通常是 `1 行 2/3 列表格 + 中间公式 + 右侧编号`。
  - 一旦给它写入 `tblBorders.top/bottom=single`，WPS 就会渲染成用户可见的粗横线。

- 图 2.1 前出现整块大空白
  - 根因不是图块上下间距，而是图块原本挂在较晚的正文引用后面。
  - 旧的 `layout_rebalance` 只认“最近一次引用”，且遇到 `h3/h4` 或误判标题的正文就提前停止回扫。
  - 结果是图块虽然满足“出现前已引用”，但仍停在更靠后的锚点，页底留白无法被吃掉。

- 图 2.1 后方又出现新的整页空白
  - 根因不是图块再次跑版，而是 `2.2.1` 残留了旧文档里的 `pageBreakBefore`。
  - 之前只跑 `figures_tables` 时，这个标题级分页属性不会被清理。
  - WPS 渲染时把 `2.2.1` 整段推到下一页，导致 `2.2` 独自留在上一页底部。

### 9.2 这次是怎么定位出来的

这次确认了一条更可靠的排查链：

1. 先跑工具审查，确认结构规则是否已过。
2. 再用 WPS 打开或导出 PDF，看是否还有“规则层过了，但渲染层仍难看”的问题。
3. 对于公式横线：
   - 直接解包 DOCX，检查相关 `w:tbl` 是否属于 `equation layout table`。
   - 重点看 `w:tblPr/w:tblBorders` 是否被写成了普通三线表。
4. 对于图表留白：
   - 不只看图题/图注的 spacing。
   - 要同时看：
     - 图块当前锚点在正文中的位置
     - 是否被 `h3/h4` 或误判标题提前截断
     - 图后是否紧跟带分页属性的后续标题
5. 对于页底整块空白：
   - 优先查后续标题段落的 `pageBreakBefore/keepNext/keepLines`
   - 不要先假设是图块留白逻辑失败

### 9.3 这次沉淀到工具中的能力

本轮已经内化进主链和回归的点包括：

- 公式布局表边框保护
  - 公式布局表会跳过普通三线表修复。
  - 若历史文档里已经带上边框，会主动清成 `nil + sz=0`。

- 图块重排锚点改进
  - `layout_rebalance` 不再只停在最近一次引用。
  - 现在会在同一 `h2` 小节内尽量取更早的有效引用锚点。
  - `h3/h4` 不再阻断回扫。
  - 对“文本像标题、但实际上是正文引用句”的误判更稳健，不会过早截断。

- 已有引用不再重复插兜底句
  - 对 `图 2.1 A、B` / `图2.1C` 这类带空格、带子图标记的引用也能识别。
  - 避免再额外插入“相关结果如图2.1所示。”这类生硬段落。

- 标题残留分页清理
  - 普通正文标题在修复时会清除遗留的 `pageBreakBefore`。
  - 只有一级章节首页等明确需要分页的场景，才重新显式加分页。

### 9.4 这次新增回归的价值

这轮最重要的不是单次修文档，而是事故回归已经覆盖了：

- 公式布局表不能被套三线表边框
- 图块可跨 `h3` 前移到更早引用点
- 已有 `图 2.1 A/B/C` 引用时不再插兜底句
- 普通 `h2/h3/h4` 标题修复时会清掉遗留 `pageBreakBefore`

结论：

- 以后再遇到“WPS 里有横线 / 有大空白 / 图表没有跨页但版面仍难看”的问题，不要只盯 spacing。
- 必须把排查分成：
  - 对象块位置
  - 标题分页属性
  - 公式布局表伪装成普通表格

### 9.5 后续执行建议

以后凡是用户明确说“以 WPS 的排版结果为准”，推荐流程应改为：

1. 先跑目标 scope 的结构修复
2. 若涉及图表，优先考虑同时带：
   - `--scope figures_tables`
   - 必要时再加 `--scope headings`
   - `--layout-rebalance`
3. 再用 WPS 导出 PDF 验证
4. 若仍有大空白：
   - 先查后续标题是否残留 `pageBreakBefore`
   - 再查图块锚点位置
   - 最后才回头看 spacing

当前稳定策略：

- 表格伪标题风险：打印警告，但继续执行
- 样式/文本层级冲突：在 `headings + --renumber-headings` 下可阻断
- `--force`：保留人工旁路能力

### 9.6 正文改动后要按“正文 + 标题 + 图表”联动复跑

本轮又确认了一件后续会反复发生的事：

- 一旦用户回头改正文内容，尤其是第二章实验结果中的描述句、图表引用句、图注/表注文字
- 后面的图表排位、题注间距、引用上标、局部留白都可能重新变化

结论：

- 以后不要把图表排版问题视为“一次修完永久稳定”
- 只要正文内容发生变化，就应把它视为一次新的联动排版任务

推荐最小联动链：

1. 先跑 `body_paragraphs`
2. 再跑 `headings`
3. 再跑 `figures_tables --layout-rebalance`
4. 最后用 WPS 打开或导出 PDF 复核第二章实验结果

如果想一步到位，当前更稳的组合是：

- `--scope body_paragraphs`
- `--scope headings`
- `--scope figures_tables`
- `--layout-rebalance`

### 9.7 本轮新增到主链的两个细节能力

这次除了图表锚点和公式布局表边框，还新增了两个以后很容易重复踩到的修复点：

- 含公式的受保护正文段也要继续修正文引用
  - 之前这类段落为了保护公式，不会走 `split_inline_citations`
  - 结果像 `……表示[45]。` 这种引用会残留在正文 run 中，不会上标
  - 现在已经改成：
    - 保留公式对象
    - 同时继续拆分正文中的 `[45]` 为独立上标 run
    - 并继续处理正文中西文/数字间距

- 图表注释段也要补中数字间距
  - 之前图注/表注段只修字号、行距、居中
  - `注1)` 这类写法不会自动变成 `注 1)`
  - 现在图表注释也会补 `SP_NUM_CJK` 相关间距

- 图表注释识别要容忍 `注 ：` 这类冒号前空格
  - 有些 WPS/人工修改后的表注会写成 `注 ：说明文字`
  - 如果只识别 `注：`，这类段会被误判成普通正文
  - 后果是表块留白修复会把它当成“表后正文第一段”，错误补出一行段前距
  - 现在图表注释识别兼容 `注：`、`注 ：`、`注1)`、`注 1)` 等变体

工程意义：

- 以后再改实验结果正文，不容易出现“公式没坏，但引用格式回退了”
- 以后再改图注/表注，不容易出现“版心正常，但注释细节又不合规”

### 9.8 公式说明段不能再保留数学框字体污染

本轮又确认了一个之前容易漏掉的点：

- 真正的公式本体格式正确，不代表公式下方“其中/式中”说明段也正确
- 这类说明段里经常混入很多内嵌 `oMath` 小公式对象
- 一旦这些小对象带着 `Chalkboard`、`Times New Roman Regular`、`DejaVu Math TeX Gyre` 等字体信息保存进文档
- WPS/Word 中就会表现成：
  - 英文字母不是 `Times New Roman`
  - `m1/m2/V1/A10/W0` 里的后缀没有按正文说明习惯落成下角标

这次已经沉到主链的处理方式：

- 对以 `其中` / `式中` 开头的公式说明段，单独做符号归一化
- 若段内有小型 `oMath` 对象：
  - 不再保留它们的数学框字体
  - 直接改写为正文风格的普通字符 run
- 对变量记号：
  - 英文字母统一 `Times New Roman`
  - 后缀数字或 `t/r` 统一改成下角标

覆盖到的典型写法包括：

- `m0/m1/m2`
- `W0/Wt/Wr`
- `A0/A10`
- `V0/V1/V2`

工程结论：

- 以后再遇到“公式下方解释里的字母字体怪、后缀不是下标”的问题，应直接视为工具问题
- 不应再靠人工逐个公式说明段修

### 9.9 封面进入固定保留模式

这轮还确认了一条后续协作约束：

- 不只是你和刘佳轾这套辽宁大学论文
- 后续再用论文格式修改工具处理任何人的论文时，都不应再自动改封面内容
- 原因不是学校差异，而是封面个体差异太强，工具自动改封面很容易越改越坏

当前主链处理改为：

- 所有 profile 默认保留现有封面
- 不再自动做封面段落行距归一化
- 不再自动缩放封面图形
- 默认只修正文、目录、图表、参考文献、摘要等正文链路

结论：

- 以后不管是谁的论文，只要是在继续迭代正文、目录、图表、参考文献，封面都应保持原样
- 除非用户明确要求改封面，否则工具不再碰封面

### 7.2 伪标题规则必须只有一个判定源

本轮已把以下能力收敛到同一套底层判断：

- `match_heading_by_text`
- `HeadingCandidateFilter.is_false_heading_text`
- `HeadingCandidateFilter.candidate_reason`
- `should_skip_for_renumber`

新增经验：

- 不要让“是否是假标题”和“为什么是假标题”分成两套手写正则
- 否则会出现：
  - diagnose 说有风险
  - fix 链却按安全处理
  - 或 diagnose 没标出来，但 fix 链在跳过

### 7.3 小数值也应被明确标记，而不是落成模糊风险

本轮新增了 `decimal_value` 原因标签。

含义：

- 像 `231.112323` 这种纯小数值
- 不应被视为正文标题
- 在诊断摘要中应明确说明原因，而不是只显示成模糊的 `table_heading_like`

这有助于后续快速区分：

- 科学计数法
- 化合物名
- 纯小数值

- 定向回归通过
- 全仓回归通过
- 真实辽大文档抽测通过

## 8. 追加记忆：参考文献专项规则内化的经验

### 8.1 辽大参考文献必须视为独立专项链，不应混在正文规则里

本轮确认：

- 参考文献的编号、悬挂缩进、段前后、行距、英文半角标点，都是辽大专项规则
- 不应继续依赖正文规则或通用 `CN-Common` 默认值“顺带修到”

结论：

- 辽大参考文献要求必须进入当前主 profile `lnu-checker-2026.yaml`
- 旧 `lnu-undergraduate` 入口已移除，不再维护第二套规则文件
- 同时进入 `audit_thesis.py`、`fix_thesis.py` 和回归测试

### 8.2 悬挂缩进方向对了，不代表观感已经对

本轮最大的实际修正不是“从无到有支持悬挂缩进”，而是把悬挂值从默认兜底的 `560 twips` 收到更接近辽大样图的 `420 twips`。

确认结果：

- `560` 会让第二行内缩过深，视觉上偏“里出外进”
- `420 / -420` 更接近样本文档“第二行需要缩进对齐即可”的观感

结论：

- 后续遇到辽大参考文献观感不顺眼时，先查 `ref_hanging` 是否真的来自 profile，而不是继续吃默认值

### 8.3 配置写进 profile，不代表运行时真的吃到了

本轮暴露出一个实际问题：

- profile 即使写了 `ref_hanging`
- 运行时若 `build_profile_cfg()` 没有把该字段加入加载白名单
- 最终修复仍会继续使用默认 `560`

结论：

- 每次新增学校专属参数时，都要同步检查：
  - profile 是否写入
  - `build_profile_cfg()` 是否加载
  - fix / audit 是否真的消费
  - 测试是否覆盖“运行时已生效”这一层

### 8.4 编号规范必须同时覆盖“补零”和“多空格”

本轮真实文档里出现了两类问题：

- `[01]`、`[02]`
- `[1]   内容`

如果只修前导零，不收多空格，最终仍会出现前半段与后半段视觉不一致。

结论：

- 参考文献编号规则应统一为：
  - `[N]`
  - 后直接接正文内容

### 8.5 参考文献标题本身也可能是事故点

本轮处理 `毕业论文初稿_含第四章_新工具修复版_v13_图规则主链验证.docx` 时确认：

- 参考文献条目已经进入正文流
- 但标题不是 `参考文献`
- 而是一个占位符 `——`

这会导致：

- 条目格式完全正确
- 但视觉上仍不符合辽大样图

结论：

- 后续处理参考文献时，不能只看条目段落
- 还要检查标题是否为标准 `参考文献`
- 若出现 `——`、空段或其他占位文本，需要单独补正

### 8.6 当前已沉淀的参考文献专项状态

已稳定：

- `LNU_REF02`
  - 拒绝补零编号
  - 拒绝编号后多个空格
  - 拒绝 `Tab`
- `LNU_REF03`
  - 检查五号字号
  - 检查 `1.5` 倍行距
  - 检查段前 `0`
  - 检查段后 `0`
- `fix_reference_paragraph()`
  - 会统一去补零
  - 会收掉编号后的多余空格
  - 会应用 `420 / -420` 悬挂缩进
  - 会设置段前后 `0`

仍未完全主链化：

- 参考文献标题占位符 `—— -> 参考文献` 的自动修正

### 8.7 后续推荐执行方式

针对辽大论文的参考文献，优先这样执行：

```bash
python3 - <<'PY'
import sys
sys.path.insert(0,'/Users/apple/Desktop/论文格式检查工具/scripts')
import fix_thesis
fix_thesis.fix_docx('输入.docx', '输出.docx', profile_path='lnu', scopes=['references'])
PY
```

之后至少抽查：

- 标题是否为 `参考文献`
- 前 1-3 条条目的：
  - `left_indent`
  - `first_line_indent`
  - `space_before`
  - `space_after`
  - `line_spacing`

目标值：

- `left_indent = 420`
- `first_line_indent = -420`
- `space_before = 0`
- `space_after = 0`
- `line_spacing = 1.5`

## 9. 追加记忆：摘要学名斜体与图表分页保护

### 9.1 中文摘要正文不能整段斜体

- 中文摘要正文默认按正常正文处理。
- 只有菌种学名片段保留斜体，例如：
  - `Microbispora triticiradicis`
  - `M. triticiradicis`
- 若中文摘要首段整段发斜，优先检查 `fix_abstract_body()` 是否继承了旧 run 的斜体属性。

### 9.2 图表不是散段，必须按对象块处理分页

- 普通图块不能跨页拆开：
  - 图片段
  - 图题
  - 图注
- 普通短表块不能跨页拆开：
  - 表题
  - 表头/表体
  - 表注
- 长表才允许续页。
  - 续页时必须重复表头。

### 9.3 当前主链处理原则

- `figures_tables` 修复链除了留白重排、先引后放、表头重复外，还要补分页保护属性：
  - 段落 `keepNext`
  - 段落 `keepLines`
  - 表格行 `cantSplit`
- 以后如果再出现“表题/图题留在上一页、对象主体掉到下一页”的截图，不要只查留白和前移逻辑，要优先查对象块分页保护链。
