## Lessons

- Put agent names first in thread titles, for example `计划Agent / 前端优化-2026-06-18`, so sidebar scanning starts with role.
- Each lane needs a worklog entry before handoff; ledger alone records messages but not what the agent learned.
- Direct handoffs are the default: planning sends to execution, execution sends to review, review sends to arbitration.
- Reverse messages are normal when downstream evidence shows an upstream artifact is wrong.
- `经理Agent` should monitor and recover, not become a bottleneck that all messages pass through.
- A loop may start in one bootstrap thread, but that does not create a permanent main agent.
- The real workflow is owned by the phase lanes and their direct handoffs.
- If concurrent appends create duplicate worklog sequence numbers, repair the numbering explicitly instead of leaving ambiguous records.
- Distinguish logical handoff ownership from physical delivery: a Dispatcher can call `send_message_to_thread`, but the ledger must still name the lane whose artifact caused the handoff.
- `worklog`, `ledger`, `artifact`, and `baton` are separate: worklog is continuous lane history, ledger is cross-lane message accounting, artifact is formal phase output, and baton is a recovery checkpoint for context or handoff risk.
