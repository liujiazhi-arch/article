# Frontend UI Style Guide

本文件记录本项目前端的字体、文案、玻璃态界面和主题资产规范。它沉淀的是用户已经明确认可的方向，用来避免后续前端工作重复踩同样的问题。

## 适用范围

- 本地论文工具的前端原型和正式前端
- 主题页面、工作台、历史任务、PDF 复核、结果页
- 字体、字号、字重、行距、卡片密度、玻璃态面板、背景图和主题资产

## 前端 Skill 工作流

后续处理前端时，先按任务触发对应 skill，再进入实现。

推荐顺序：

1. `frontend-architecture-rules`
   - 定义修改范围、组件边界、token、主题、验证方式
   - 防止为一个局部问题引入新的框架或无关重构
2. `impeccable-image-theme`
   - 用在图片驱动的主题、配色、材质、字体气质、组件语言提取
   - 从参考图或生成图提炼视觉方向
   - 判断 UI 是否真正匹配主题图
3. `gpt-image-2-generator` 或系统图像生成能力
   - 当现有图片不够时生成成套资产
   - 不要零散生成互不匹配的单图
4. `image-to-code-skill`
   - 当需要把视觉稿或生成图落成页面结构时使用
5. `playwright` 或 Browser
   - 对本地页面做真实截图、控制台检查、响应式检查

`taste-skill` 可以辅助判断审美，但不能覆盖本文件已经沉淀的学生视角、字体大小、文案短句、玻璃态可读性和主题资产一致性要求。

## 图像驱动主题流程

本项目后续做主题化前端时采用下面的主流程：

```text
参考网站图 / 截图 / 生成图
  -> 提取视觉方向
  -> 生成或补齐配套图
  -> 定主题 token
  -> 定配色 字体 材质
  -> 生成匹配 UI 组件
  -> 浏览器截图校验
```

### 视觉方向提取

从参考图或生成图中提取：

- 色温：冷灰蓝、暖银杏、清晨浅雾、雪景冷白等
- 材质：玻璃、湿润石板、纸张、亚克力、雪、胶片、档案袋
- 字体气质：学生工具、校园档案、安静、清晰、不要过度科技感
- 组件语言：按钮、标签、状态卡、流程卡、下载卡、历史记录
- 空间节奏：哪里密集、哪里留白、哪里必须清楚可读

提取时要区分：

- 氛围色：服务背景和材质
- 语义色：服务按钮、提醒、通过、错误、焦点

不要把氛围色直接滥用成所有按钮和所有文字颜色。

### 成套资产

一个主题至少考虑这些资产角色：

- hero 大背景
- 功能地图母版
- 工作台 workflow board
- PDF 复核 board
- 历史任务 board
- 结果页 result board
- 小型材质纹理或状态卡背景

现有图片不够时，先判断能否复用同主题已有图并加深色遮罩。仍不够时再生图。

生图时要成套生成，保持同一主题的光线、材质、色温、构图和负空间。不要生成单张漂亮但无法放进整套 UI 的图。

### 生图触发条件

出现这些情况时可以生图：

- 某主题只有 hero，没有 workflow / pdf / result 内部背景板
- 当前页面继承了另一个主题的暖色或冷色资产
- 背景图缺少可放 UI 的负空间
- 图片材质与 UI 材质冲突
- 通过遮罩仍无法解决不搭的问题

先生成最少必要数量。通常优先生成：

1. workflow board
2. result board
3. pdf board

历史页可以先复用 result board 或同主题资产板，除非用户明确指出历史页要独立叙事。

## 产品语境

用户是正在处理论文终稿的学生。界面要让学生快速知道：

- 我现在该做什么
- 系统正在处理什么
- 哪些结果可以下载
- 哪些地方还需要我人工确认

不要把界面写成设计资产板、开发调试页或后端状态面板。

## 文案规则

### 学生视角

优先使用学生能直接理解的表达：

- `上传论文开始修正`
- `先看修复方案 再选择处理范围`
- `处理进度`
- `下一步提示`
- `需要你确认`
- `报告文件`
- `问题位置`

避免这些表达：

- `不是给学生看的设计资产板`
- `普通学生`
- `任务轮询`
- `/jobs/{id}`
- `queued running failed succeeded`
- `JSON`
- `bbox`
- `report artifact`
- `rule_id`

开发态术语如果必须保留，只能出现在开发说明、调试模式或代码注释中，不应出现在学生主界面。

### 中文标点

学生可见 UI 中，中文同一可视行尽量不要出现逗号、句号、冒号、顿号等标点。需要表达停顿或并列时，用这些方式替代：

- 拆成两行
- 拆成多个卡片
- 拆成标题加说明
- 用空格分隔短语

推荐：

```text
上传论文开始修正
先看修复方案 再选择处理范围
```

不推荐：

```text
把 .docx 放进修正舱，先生成修复方案，再选择范围并启动任务。
```

## 字体与字号

阅读优先，不追求装饰性的细小科技感。

建议范围：

- 页面主标题：28-40px，字重 680-780
- 面板标题：24-36px，字重 700 左右
- 卡片标题：16-17px，字重 760-820
- 重要正文说明：15-16px，行高 1.55-1.7
- 步骤块文字：15px 起，副说明 12-13px 但必须高对比
- 标签和元信息：11-12px 只用于不影响理解的辅助信息

不要把重要说明压到 11-12px。用户已经明确反馈，小字会让人不想读。

### 主题主标题

封面或主题页的大标题不是通用组件换色。每个主题的主标题都要有自己的字体气质、颜色温度和材质细节。

要求：

- 银杏主题可以偏书卷、档案、暖金与深绿，标题允许更厚重
- 雨后主题要冷灰蓝、湿润、克制，标题线条应更利落
- 清晨主题要柔光、暖白、雾绿，标题应更轻更安静
- 雪景主题要冷白、清透、边缘清晰，标题可以更亮但必须可读
- 标题差异不能只靠 `--headline-a` / `--headline-b` 换两个颜色
- 如使用标题下划线、光带、描边或阴影，也必须跟随主题材质变化
- 不使用负字距；需要主题差异时通过字体族、字重、色温、阴影、光带和背景遮罩完成
- 学校名应作为整体排版，例如 `辽宁大学` 必须放在同一行，不能被浏览器自动拆成 `辽宁大` / `学`
- 长标题优先拆成有语义的固定行，例如 `辽宁大学`、`毕业论文`、`格式修正器`，不要交给一段文本自动换行

## 透明与对比度

玻璃态 UI 的重点是背景有层次，文字仍然清楚。不要把文字也做成过低透明度。

推荐：

- 玻璃面板使用稳定深色底，例如深色半透明层叠背景
- 重要正文颜色接近 `rgba(255,255,255,.76)` 到 `.88`
- 标题使用高对比颜色
- 背景图复杂时，在内容区域增加深色内衬或伪元素遮罩

避免：

- 文字颜色过淡
- 背景纹理直接压在正文后面
- 白色实底卡片突然出现在深色玻璃主题中
- 面板透明到无法形成阅读区域

## 布局密度

不要把信息都堆在上半部分，也不要在下半部分留下无意义空白。空间应该服务于阅读节奏。

工作台类页面：

- 中央主操作区要清楚突出，但不能用突兀白底
- 流程步骤要大、可读、有副说明
- 底部空间可以承载流程、日志、状态说明，避免空着

右侧状态栏：

- 不写技术轮询信息
- 用学生能理解的三类状态组织，例如 `处理进度`、`下一步提示`、`需要你确认`
- 状态卡片要纵向占满可用区域，不要都挤在顶部

历史页：

- 历史任务列表要像可读记录，不像压缩日志
- 任务标题和说明字号要足够大
- 背景图不能干扰任务文字

结果页：

- 结果状态要稳重清晰
- 下载入口、报告、PDF 复核、下一步应分块展示
- 不要用和当前主题不匹配的浅色纸张大面板

## 主题资产

每个主题都应有完整一致的资产链路。新增或调整主题时，至少检查：

- `--hero-image`
- `--asset-board`
- `--asset-workflow-board`
- `--asset-pdf-board`
- `--asset-result-board`
- 对应的 background position / focus 变量

错误经验：

- 只替换大背景，不替换内部功能背景板
- 雨后主题继承银杏或清晨的暖色内部板
- 结果页背景和左右面板配色不一致

正确方向：

- 雨后主题使用冷灰蓝、湿润、深色玻璃质感
- 雪景主题可以使用专属雪景资产
- 资产不够时，先复用同主题已有图并加强遮罩；仍不够再生图

## 已确认的正确改法

这些方向已经在本轮调整中验证过，后续可以复用：

- 功能地图从长段解释改为“学生会用到的六个功能入口”
- 功能说明使用短标题加一行说明卡片
- 工作台白色 `.docx` 卡改为深色半透明玻璃卡
- 步骤条改成更大的步骤卡，并加短副说明
- 右侧状态从技术词改为学生可理解的三类提示
- 雨后主题补齐内部背景板变量，不再继承暖色资产
- 结果页使用深色稳定玻璃层压住背景纹理，保证文字优先可读

## 不要沉淀的错误经验

这些是已经被指出的问题，不应在后续前端中复用：

- “这一页不是给学生看的设计资产板”这类脱离用户语境的文案
- 大段文字堆在玻璃面板中
- 重要说明使用 11-12px 小字
- 同一行中文里堆多个标点
- 技术状态和后端字段直接暴露给学生
- 白色实底卡片打断深色玻璃主题
- 页面上半部分拥挤 下半部分空
- 主题只换大背景 内部卡片图仍沿用其他主题

## 已确认视觉基线的文件治理

`scripts/article_api/static/styles/layout.css` 当前保存用户已确认的页面布局和四主题视觉基线。它属于需要逐步迁移的旧样式文件，不再承接新功能样式；新功能应使用独立的职责文件，例如 `format-radar.css`。

为避免架构整理再次改变现有外观：

- 当前基线 SHA256 为 `e404b51d64378834832c2abd6b892b3b6396702abeecc21f7c0eec7a741d1ae7`
- 仅在用户确认视觉变化并完成桌面截图复核后更新该指纹
- 不通过复制规则或叠加补丁样式来模拟拆分
- 后续拆分必须保持原规则顺序，并用关键页面截图和控制台检查证明视觉等价
- 在视觉等价验证链路建立前，只冻结旧文件；新增职责放进独立样式文件

## 前端修改验收清单

完成前端修改前，至少检查：

- 主要学生可见文案是否去掉开发态术语
- 中文可见行是否避免标点堆叠
- 重要正文是否不小于 15px
- 卡片标题是否足够突出
- 玻璃面板中文字是否有足够对比度
- 是否存在大段文字堆叠
- 是否存在上半部分拥挤而下半部分空的布局
- 当前主题下内部背景板是否与大背景匹配
- 浏览器中检查目标页面无明显重叠、溢出和控制台错误
